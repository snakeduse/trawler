# discovery-cli Specification

## Purpose
Позволить пользователю находить отвечающие хосты отдельной командой с видимым прогрессом и машиночитаемыми результатами общего Erlang-ядра.

## Requirements

### Requirement: Команда discover
CLI должен (SHALL) предоставлять `discover --targets <TARGETS>` с `--method auto|arp|icmp|tcp|raw_tcp`, `--ports` для TCP connect, `--timeout`, `--concurrency`, `--retries`, `--json`, `--verbose`, `--no-progress`. Метод по умолчанию — auto. Неверные и повторные опции должны (SHALL) возвращать код 2 до проб; scan сохраняет поведение.

#### Scenario: Loopback и проверка опций
- **WHEN** discover получает корректную loopback-выборку с методом tcp либо неверные/повторные опции
- **THEN** использует общий API либо возвращает код 2 соответственно

### Requirement: Находки и прогресс
Текстовый режим должен (SHALL) показывать каждый обнаруженный IP, метод подтверждения и MAC при наличии сразу, остальные исходы — только с verbose. В stderr должен (SHALL) отображаться прогресс по адресам и прошедшее время: одна строка в терминале, редкие строки без ANSI при перенаправлении. no-progress отключает прогресс.

#### Scenario: Потоковый вывод
- **WHEN** найдена первая цель, пока остальные ещё проверяются
- **THEN** находка и периодический прогресс видны до завершения
- **AND** прогресс продолжает обновляться без новых результатов и при постоянном потоке событий

#### Scenario: Терминал и перенаправление
- **WHEN** stderr подключён к терминалу либо перенаправлен
- **THEN** строки находок не повреждаются либо отсутствуют ANSI/возврат каретки соответственно
- **AND** итог показывает полное количество проверенных адресов

### Requirement: JSON и диагностика
JSON должен (SHALL) быть одним объектом с полными сортированными `results` и `summary`, строковыми IP и методами, MAC при наличии и предупреждениями в сводке, без прогресса. Предупреждения о fallback и ошибки должны (SHALL) направляться в stderr. Завершённый поиск имеет код 0 независимо от числа находок, ошибка выполнения — 1.

#### Scenario: Машинный вывод и fallback
- **WHEN** поиск завершён с json и предупреждением о TCP fallback
- **THEN** stdout разбирается как один полный JSON-объект, а stderr содержит предупреждение без прогресса
- **AND** код выхода равен 0

#### Scenario: Недоступный явный метод
- **WHEN** выбран raw-метод без необходимых прав
- **THEN** код выхода равен 1 и stderr объясняет недоступность метода

### Requirement: Документированные ограничения
Справка и README должны (SHALL) описывать методы auto, права, Linux-ограничение raw, TCP fallback, таймаут адреса и отсутствие гарантии обнаружения молчащего хоста или идентичности с Nmap. Они должны (SHALL) различать discover и scan, не требуя Nmap для работы.

#### Scenario: Справка
- **WHEN** запрошена справка
- **THEN** пользователь видит discover, методы и смысл обнаружения в отличие от сканирования портов
