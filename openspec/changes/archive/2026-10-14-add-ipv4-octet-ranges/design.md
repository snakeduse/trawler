# Design

## Context

Мотивация приведена в proposal.md. `trawler_targets:parse_targets/1` сейчас делит бинарный ввод по всем запятым; элемент Erlang-списка представляет одну цель. Выход — отсортированные непересекающиеся включительные диапазоны IPv4. Ядро использует этот формат, поэтому менять его не требуется.

## Goals / Non-Goals

Goals: расширить чистый парсер, сохранить контракты API и существующие корректные выборки, ограничить разворачивание пооктетного произведения до его создания.

Non-Goals: менять планировщик, процессы, сокеты, таймауты, отмену, порты или публичные типы. Новых процессов, таймеров и иных ресурсов не создаётся; при ошибке парсер только возвращает значение, а существующий API не начинает пробы.

## Decisions

### Контракты

Сохраняются `parse_targets(targets_input()) -> {ok, [addr_range()]} | {error, reason()}`, `targets_input() :: binary() | [ip4() | binary()]`, `addr_range() :: {ip4(), ip4()}` и причины `{invalid_targets, term()}` / `too_many_hosts`. Кортежи IPv4 и смысл элементов Erlang-списка сохраняются: каждый бинарный элемент — одна цель, теперь также пооктетная. Только общий бинарный ввод допускает список целей.

### Разделение общего бинарного ввода

Сначала сохранить старый путь: если весь ввод корректен как прежний список отдельных IPv4/CIDR/полных диапазонов через запятую с обрезкой пробелов, принять его. Иначе разделить по ASCII-пробелу, табуляции, CR и LF; каждый непустой фрагмент разобрать как прежний список или одно пооктетное выражение. Пустой общий ввод, пустые элементы вокруг запятых и внутренние пробелы в одном выражении остаются ошибками. Это сохраняет ` IP1 , IP2 `, но не превращает `192.0.2.5 / 30` в корректный ввод. Внутри фрагмента сначала проверять синтаксис старого списка, затем пооктетный синтаксис; выбор грамматики не должен зависеть от `max_hosts`. Ошибки старого ввода по возможности сохраняют прежнюю причину, включая пустой бинарный элемент. Некорректная пооктетная цель возвращает `{invalid_targets, BadTarget}`.

Альтернативы: менять запятую на новый обязательный разделитель (ломает совместимость); эвристически разделять смешанные пооктетные выражения по запятым (усложняет грамматику и диагностику). Выбран явный пробельный разделитель.

### Грамматика одной пооктетной цели

Ровно четыре октета, разделённых точками. Октет — непустой список элементов через запятую; элемент — десятичное число 0..255 или включительный диапазон `a-b`, `a-`, `-b`, `-`. Пропущенные границы равны 0/255. Ведущие нули, знаки плюса, обратные границы, двойные дефисы, пустые элементы и пробелы внутри октета запрещены. `-1` означает 0..1. Диапазоны допустимы в любом октете. CIDR допускает только обычный одиночный IPv4, без пооктетных списков и диапазонов. Старый полный диапазон IP-IP распознаётся отдельно, не как пооктетный.

### Размер и нормализация

Сначала разобрать и нормализовать все октеты в объединения диапазонов 0..255 и вычислить произведение их уникальных мощностей. Если одна цель превышает `max_hosts`, вся выборка гарантированно превышает лимит даже после объединения: вернуть `too_many_hosts` до разворачивания этой цели. Для допустимой цели построить числовые интервалы, по возможности сохраняя непрерывные суффиксы диапазоном; не создавать более `max_hosts` адресов для одного пооктетного выражения. Объединять полученные интервалы с другими целями и проверять размер объединения, а не сумму с повторами. Большие CIDR и полные диапазоны остаются сжатыми. Желательно проверять размер объединения инкрементально, чтобы память не росла как число повторных выражений, умноженное на лимит. Превышение не требует разворачивания пространства IPv4. Ошибочный синтаксис проверяется до сетевых операций независимо от порядка целей.

Альтернатива — сначала разворачивать любое произведение — отвергнута из-за выборок вроде `-.-.-.-`.

### Проверка

EUnit: любой октет, комбинации списков и диапазонов, открытые границы, 0/255, пересечения, повторы, старые формы и пробелы, список Erlang, смешанный бинарный ввод, недопустимые значения и CIDR-комбинации. Проверять точную выборку, а не только число хостов. Небольшие произведения сверять с независимым эталонным перечислением; огромные выборки — через малый лимит и timeout теста. Проверить превышение суммарного объединения и допустимость пересекающихся целей у границы лимита.

Common Test: escript получает одно quoted-значение `--targets` с новыми выражениями и старой формой, выполняет только loopback-пробы; результат/счётчики без повторов, ошибки с кодом 2, справка. Перед CT пересобрать escript через `make cli`. Финальные проверки — `make check`, `make docs`.

## Risks / Trade-offs

- Запятая имеет две роли → явно документировать пробельное разделение новых выражений; не обещать полную совместимость CLI Nmap.
- Ранее ошибочная запись `192.0.2.-1` становится корректной → намеренно обновить тест и документацию.
- Ошибка при выборе fallback-грамматики может маскировать чрезмерную цель → разделить синтаксический разбор и лимиты.
- Рост памяти при большом числе выражений → инкрементально объединять интервалы, не материализовать чрезмерные произведения.

## Migration Plan

Миграции конфигурации и API нет. После проверок архивировать изменение с обновлением основных спецификаций. Откат — возврат изменений парсера, тестов, справки и документов; внешнее состояние не меняется.
