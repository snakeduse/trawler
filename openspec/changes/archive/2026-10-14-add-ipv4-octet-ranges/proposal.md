# Proposal

## Why

Для компактного задания IPv4-выборок нужны пооктетные диапазоны и списки, совместимые с синтаксисом Nmap. Сейчас приходится перечислять полные адреса или использовать недостаточно гибкий CIDR.

## What Changes

- Добавить числа, списки и включительные диапазоны в любом из четырёх октетов, включая пропущенные границы (0 и 255).
- Разделять новые выражения пробельными символами внутри `--targets`; сохранить старые списки полных адресов, CIDR и полных диапазонов через запятую.
- Каждый пробельный фрагмент — либо старый список, либо одно пооктетное выражение. Смешение новых выражений через запятую не поддерживается.
- Сохранить дедупликацию и проверку `max_hosts` до сетевых операций и до разворачивания чрезмерной выборки.
- Расширить Erlang API без изменения сигнатур, справку, README и тесты.
- Ранее ошибочная запись `192.0.2.-1` становится диапазоном последнего октета 0–1.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `target-selection`: пооктетная грамматика, разделители, валидация и ограничение размера выборки.
- `scan-cli`: передача смешанной выборки в одном значении `--targets`.

## Impact

Затрагиваются `trawler_targets`, справка `trawler_cli`, EUnit, Common Test и README. Формат нормализованных диапазонов, публичные сигнатуры, сетевое ядро, управление ресурсами и зависимости не меняются. DNS, IPv6, файлы целей, исключения, случайные цели, новые CLI-опции и комбинации пооктетных выражений с CIDR не входят в объём.
