## MODIFIED Requirements

### Requirement: Выбор IPv4-адресов
Сканер должен (SHALL) принимать отдельные IPv4-адреса, списки, включительные
диапазоны полных адресов, CIDR и пооктетные выражения в форматах Erlang и CLI.
Он должен (SHALL) нормализовать биты хоста в CIDR, включать все адреса подсети
и проверять каждую выбранную пару «адрес / порт» не более одного раза.

#### Scenario: Смешанные пересекающиеся адреса
- **WHEN** вызывающий объединяет адреса, диапазоны и пересекающиеся блоки CIDR
- **THEN** каждый уникальный IPv4-адрес представлен ровно один раз

#### Scenario: Границы CIDR
- **WHEN** вызывающий выбирает `192.0.2.5/30`
- **THEN** включаются адреса от `192.0.2.4` до `192.0.2.7`
- **AND** `/32` выбирает ровно один адрес

#### Scenario: Пооктетное выражение в Erlang-списке
- **WHEN** список API содержит `<<"192.0.2.1-3">>` и `{192,0,2,2}`
- **THEN** выбраны только адреса `192.0.2.1`, `192.0.2.2` и `192.0.2.3`, без повторов

## ADDED Requirements

### Requirement: Пооктетные выражения IPv4
Сканер должен (SHALL) принимать ровно четыре октета, каждый из которых задаёт непустой список чисел или включительных диапазонов через запятую. Пропущенные границы диапазона должны (SHALL) означать 0 слева и 255 справа. Значения должны (SHALL) быть десятичными числами 0..255 без ведущих нулей; повторяющиеся значения должны (SHALL) объединяться.

#### Scenario: Диапазоны в любом октете
- **WHEN** выбрана цель `10-11.20-21.30-31.40-41`
- **THEN** выбрано точное декартово произведение значений четырёх октетов

#### Scenario: Смесь списков и диапазонов
- **WHEN** выбрана цель `192.168.3-5,7.1,3-4`
- **THEN** выбраны только комбинации третьего октета из `3,4,5,7` и четвёртого из `1,3,4`

#### Scenario: Открытые границы
- **WHEN** выбираются `192.0.2.10-`, `192.0.2.-20` или `192.0.2.-`
- **THEN** последний октет соответственно принимает значения 10..255, 0..20 или 0..255
- **AND** `192.0.2.-1` выбирает октеты 0 и 1

#### Scenario: Повторы в октетах
- **WHEN** выбрана цель `192.0.2.1,1,1-3,2-4`
- **THEN** выбраны ровно четыре уникальных адреса с последним октетом 1..4

#### Scenario: Неверное выражение
- **WHEN** октет содержит 256, ведущие нули, обратный диапазон, двойной дефис или пустой элемент, либо цель сочетает пооктетный диапазон или список с CIDR
- **THEN** возвращается `invalid_targets` до сетевых проб

### Requirement: Разделение IPv4-целей
Общий бинарный ввод должен (SHALL) сохранять старые списки IPv4, CIDR и полных диапазонов через запятую, включая пробелы вокруг элементов. Иначе цели должны (SHALL) разделяться ASCII-пробелом, табуляцией или переводом строки; каждый фрагмент — старый список либо одно пооктетное выражение. Бинарный элемент Erlang-списка должен (SHALL) оставаться одной целью. Пустые элементы и пробелы внутри выражения должны (SHALL) отклоняться.

#### Scenario: Старый список
- **WHEN** передано ` 192.0.2.1 , 192.0.2.4/30 , 192.0.2.10-192.0.2.11 `
- **THEN** выборка соответствует прежнему синтаксису и не содержит повторов

#### Scenario: Новая смешанная выборка
- **WHEN** передано `192.0.2.1,3-4 198.51.100.0/30,198.51.100.7`
- **THEN** выбраны пооктетная цель первого фрагмента и старый список второго
- **AND** замена разделяющего пробела табуляцией или переводом строки сохраняет результат

#### Scenario: Некорректное разделение
- **WHEN** передано `192.0.2.1,,192.0.2.2` или `192.0.2.5 / 30`
- **THEN** ввод отклоняется как `invalid_targets`

### Requirement: Ограничение пооктетной выборки
Сканер должен (SHALL) проверять размер нормализованного пооктетного произведения до разворачивания чрезмерной цели и возвращать `too_many_hosts` при превышении `max_hosts`. Общий лимит должен (SHALL) применяться к объединению уникальных адресов всех целей до сетевых проб, а не к сумме размеров с повторами.

#### Scenario: Огромное произведение
- **WHEN** передано `-.-.-.-` при `max_hosts = 65536`
- **THEN** возвращается `too_many_hosts` без разворачивания пространства IPv4

#### Scenario: Пересечения у лимита
- **WHEN** при `max_hosts = 4` передано `192.0.2.1-4 192.0.2.2-3`
- **THEN** выборка принимается и содержит ровно четыре адреса
- **AND** добавление цели `192.0.2.5` приводит к `too_many_hosts`
