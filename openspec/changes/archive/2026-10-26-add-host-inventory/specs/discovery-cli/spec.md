# Spec Delta

## MODIFIED Requirements

### Requirement: Команда discover
CLI должен (SHALL) предоставлять `discover --targets <TARGETS>` с `--method auto|arp|icmp|tcp|raw_tcp`, `--ports` для дополнительных проверок при любом методе, `--os`, `--timeout`, `--concurrency`, `--retries`, `--json`, `--verbose`, `--no-progress`. Метод по умолчанию — auto, определение ОС выключено. Неверные и повторные опции должны (SHALL) возвращать код 2 до проб; scan сохраняет поведение.

#### Scenario: Loopback и проверка опций
- **WHEN** discover получает корректную loopback-выборку с методом tcp либо неверные/повторные опции
- **THEN** использует общий API либо возвращает код 2 соответственно

#### Scenario: Необязательные ОС и порты
- **WHEN** переданы `--os` и `--ports` с методом auto или tcp
- **THEN** включаются соответствующие дополнительные проверки без фильтрации найденных адресов

### Requirement: Находки и прогресс
Текстовый режим должен (SHALL) показывать каждый обнаруженный IP, метод подтверждения и MAC при наличии по готовности результата адреса, остальные исходы — только с verbose. При `--os` добавляется предположение об ОС с уверенностью; при `--ports` — открытые выбранные порты. Прогресс по адресам должен идти в stderr: одна строка в терминале, редкие строки без ANSI при перенаправлении. no-progress отключает прогресс.

#### Scenario: Потоковый вывод
- **WHEN** найдена первая цель, пока остальные ещё проверяются
- **THEN** находка и периодический прогресс видны до завершения
- **AND** прогресс продолжает обновляться без новых результатов и при постоянном потоке событий

#### Scenario: Терминал и перенаправление
- **WHEN** stderr подключён к терминалу либо перенаправлен
- **THEN** строки находок не повреждаются либо отсутствуют ANSI/возврат каретки соответственно
- **AND** итог показывает полное количество проверенных адресов

#### Scenario: Все порты закрыты
- **WHEN** найденный адрес имеет только закрытые выбранные порты и неизвестную ОС
- **THEN** адрес всё равно напечатан как находка, а число найденных не уменьшается

### Requirement: JSON и диагностика
JSON должен (SHALL) быть одним объектом с полными сортированными `results` и `summary`, строковыми IP и методами, MAC при наличии и предупреждениями в сводке, без прогресса. Запрошенные дополнительные данные должны сохраняться полностью: состояния портов и `os` с семейством, уверенностью и основаниями. Предупреждения о fallback и ошибки должны идти в stderr. Завершённый поиск имеет код 0 независимо от числа находок, ошибка выполнения — 1.

#### Scenario: Машинный вывод и fallback
- **WHEN** поиск завершён с json и предупреждением о TCP fallback
- **THEN** stdout разбирается как один полный JSON-объект, а stderr содержит предупреждение без прогресса
- **AND** код выхода равен 0

#### Scenario: Недоступный явный метод
- **WHEN** выбран raw-метод без необходимых прав
- **THEN** код выхода равен 1 и stderr объясняет недоступность метода

#### Scenario: Дополнительные данные в JSON
- **WHEN** поиск завершён с `--json --os --ports`
- **THEN** JSON содержит найденные адреса, все выбранные порты с исходами и структурированное предположение об ОС

### Requirement: Документированные ограничения
Справка и README должны (SHALL) описывать методы auto, права, Linux-ограничение raw, TCP fallback, общий таймаут адреса, `skipped`, отключаемую эвристику ОС и отсутствие гарантии обнаружения молчащего хоста или идентичности с Nmap. Документация должна различать discover и scan, не требовать Nmap и не обещать возможность установки ПО по одному факту ответа или предположению об ОС.

#### Scenario: Справка
- **WHEN** запрошена справка
- **THEN** пользователь видит discover, методы и смысл обнаружения в отличие от сканирования портов
- **AND** указано, что ОС — приблизительное предположение, а порты не фильтруют найденные IP
