# Design

## Context

См. `proposal.md`. Сейчас фасад `trawler_discovery` нормализует опции, координатор выдаёт один глобальный слот на воркер адреса, воркер определяет маршрут и выполняет пробы. Воркер посылает один результат; после его `DOWN` координатор освобождает слот и учитывает адрес. CLI уже имеет потоковый текст, отдельный прогресс и полный JSON. Зависимостей кроме kernel/stdlib нет.

## Goals / Non-Goals

Goals: сохранить существующие lifecycle и единицу прогресса; дополнительные проверки не должны превращать найденный адрес в ошибку или умножать число процессов/сокетов. Явные порты используют существующий parser и могут включать диапазоны и более 16 значений.

Non-Goals: полноценный TCP/IP fingerprinting Nmap, SMB/NTLM-клиент, активная идентификация произвольных протоколов, аутентификация, установка ПО и гарантии скорости реальной корпоративной сети.

## Decisions

### Публичный контракт и совместимость

Расширить существующие `trawler:discover/2` и `start_discovery/2`, не создавать параллельный inventory API. `scan` не менять. Новая опция `os_detection => boolean()` по умолчанию false. `ports` допустима при любом методе и означает дополнительные проверки найденных адресов; при tcp и TCP fallback этот же явный набор участвует в первоначальном обнаружении, где достаточно первого open/refused. Без явного набора tcp/fallback остаются на 80/443 и НЕ включают дополнительный перебор портов.

В нормализованных внутренних опциях `ports` присутствует только при явном вводе; `probe_ports` для tcp/auto содержит явный набор либо [80,443]. Для arp/icmp/raw_tcp `probe_ports` отсутствует: транспорт по-прежнему не принимает порты с этими методами. Только фасад разрешает их как дополнительные проверки. Ограничение 16 убрать из фасада и `trawler_discovery_probe:normalize_ports/1`; проверку номеров сохранить. Список допустимых номеров и уникальность уже ограничивают набор 65535 значениями. Большие наборы обходить линейно, не пересчитывая длину остатка на каждом шаге.

Старые поля и события не меняются. Только `up` получает:
- при явных ports: `port_results => [#{port := 1..65535, state := open | closed | timeout | unreachable | error | skipped, elapsed_ms := non_neg_integer(), reason => term()}]`, сортировано по номеру; `open_ports => [1..65535]` содержит только открытые ЯВНО выбранные порты;
- при os_detection: `os => #{family := windows | linux | unknown, confidence := medium | low | none, evidence := [binary()]}`.

При обычном старом запросе этих полей нет. Необнаруженные адреса не обогащаются. Совокупный `elapsed_ms` включает дополнительные проверки. Сводка и счётчики остаются по адресам.

### Модуль дополнительных проверок

Новый модуль `trawler_host_inspection` с типами и двумя экспортами:

- `inspect(IP, RequestedPorts, OSDetection, Deadline) -> map()`, где IP — IPv4-кортеж, RequestedPorts — `undefined | [1..65535]` (уже проверенный уникальный список), OSDetection — boolean, Deadline — абсолютное целое монотонное время в мс. Возвращает только дополнительные поля выше. Нормальные ошибки соединения отражает в исходах, а не бросает исключения.
- `classify(Observations) -> OSMap`, где Observations — список карт `#{port := 1..65535, state := atom(), banner => binary()}`. Это чистая функция; экспорт нужен для fixture-тестов эвристики, не новый пользовательский API.

Если os_detection=false и RequestedPorts=undefined, вернуть пустую карту без сокетов. При os_detection=true добавить к рабочему набору [22,135,139,445,3389,5985,5986]; не добавлять автоматически 1000 портов. Объединение уникальное, один порт проверяется один раз. Явно выбранные порты приоритетны, затем остальные служебные; итог port_results сортируется отдельно.

В каждый момент работает один пассивный `gen_tcp` сокет. На попытку соединения и чтение вместе отводится не больше min(200 мс, оставшийся бюджет / оставшееся число рабочих портов), минимум 1 мс только при положительном остатке. Пересчитывать остаток после каждого вызова, не начинать операцию за deadline. `after` закрывает сокет. Никаких логинов и отправки протокольных данных. При включённом OS detection читать SSH identification на 22 и явно выбранных открытых портах; чтение ограничить 4096 байтами и абсолютным сроком попытки, поддержать TCP-фрагментацию и окончания строк. Сохранять только ограниченный внутренний banner для классификатора, не публиковать сырые данные.

Если бюджет исчерпан, все ещё не проверенные явные порты получают skipped, elapsed_ms=0, reason=budget_exhausted. Ошибки соединения: econnrefused -> closed; timeout -> timeout; enetunreach/ehostunreach -> unreachable; прочие -> error с reason. OS вычислять по уже полученным наблюдениям даже при исчерпании срока.

### Первая эвристика ОС

Это явно приблизительный результат, а не доказательство. Валидная SSH identification `SSH-2.0-...` или `SSH-1.99-...` с OpenSSH_for_Windows/Windows даёт windows/medium; явные Linux или Ubuntu/Debian/Fedora/CentOS/RHEL/RedHat/Alpine/SUSE дают linux/medium. Явные FreeBSD/OpenBSD/NetBSD/Darwin/macOS дают unknown/none и не должны превращаться в linux из-за порта 22. Противоречивые явные признаки -> unknown/none. Явный известный признак сильнее предположения по порту.

Без явного баннера открытый 22 — linux/low; открытый любой из 135,139,445,3389,5985,5986 — windows/low. Одновременные признаки обеих семей -> unknown/none. Нет признаков -> unknown/none. Неподходящие/повреждённые байты не дают banner-признака. Evidence — только собственные безопасные метки вроде `tcp_open:22`, `ssh_banner:linux`, `ssh_banner:windows`, `ssh_banner:other`, не произвольные строки удалённого устройства. Generic OpenSSH не даёт medium. Более сложный fingerprinting отложен, так как пользователь принимает ошибки, а приоритет — обнаружение адресов и скорость.

### Встраивание в воркер и жизненный цикл

Воркер создаёт один абсолютный Deadline=Start+timeout_ms, использует существующую route/probe логику с остатком. После `up` вызывает inspect с ТЕМ ЖЕ deadline и нормализованными явными ports/os_detection. После no_response/error инспектор не вызывается. Слот планировщика удерживается до окончания инспектора: параллельных сокетов на адрес не появляется. Итоговое событие всё ещё одно и отправляется перед `DOWN`; completed растёт только после `DOWN`.

Ошибки сети инспектора не меняют `state=up`. Защитная обработка неожиданного исключения инспектора сохраняет up, выдаёт `inspection_error` с причиной, skipped для ещё неизвестных явных портов и unknown при запрошенной ОС; не скрывает ошибку как отсутствие хоста. CLI JSON сериализует inspection_error так же безопасно, как reason.

Отмена/deadline/выход владельца/получателя/остановка приложения используют уже существующее убийство linked worker и ожидание DOWN до terminal event. Владение TCP-сокетами у этого воркера обеспечивает закрытие при kill. Не добавлять detached-процессы, nested scans, новые monitors и таймеры. Проверить lifecycle именно во время чтения баннера, а не только на фазе обнаружения.

### CLI и документация

`--os` — неповторяемый флаг, транслируется в os_detection=true. Убрать прежний запрет --ports вне --method tcp. Отображать прежние столбцы и добавлять ОС/уверенность и открытые выбранные порты только по запрошенным опциям, не менять снимки статуса на счётчики потока. Для unknown печатать unknown; для распознанной семьи явно показывать уровень предположения. JSON конвертирует атомы в строки и сохраняет полный список port_results, open_ports и os; прогресс по-прежнему только stderr. Подробности ошибок портов доступны в JSON; не печатать отдельную находку на каждый порт.

README/справка/EDoc объясняют отключение классификации, слабость портовых признаков, отсутствие фильтра по открытым портам, skipped и общий timeout. Добавить пример вызова с --os/--ports, не выдавая иллюстрацию за реальный замер.

## Risks / Trade-offs

- Эвристика по портам путает Samba, SSH на Windows и сетевое оборудование -> low/medium, основания, unknown при конфликте и документированные ограничения; не объявлять пригодность к установке.
- Дополнительные проверки замедляют найденные адреса -> по умолчанию выключены, общий deadline, только небольшой служебный набор при --os.
- Большой явный набор не успевает за timeout -> полные явные skipped; пользователь может увеличить timeout, не скрывать усечение.
- ARP в реальном Ethernet и 10000 устройств не проверяются локальным тестом -> loopback подтверждает контракты и ограниченность ресурсов, но не корпоративную полноту/скорость.

## Migration Plan

Запросы без дополнительных опций сохраняют прежнее поведение. Запросы с ports теперь получают дополнительные поля; `--ports` разрешена со всеми методами и больше не ограничена 16 портами. Обновить тесты старого запрета, не удаляя проверки некорректных номеров, повторных опций, lifecycle и прогресса. Откат — возврат к предыдущей версии без преобразования данных или инфраструктуры.
