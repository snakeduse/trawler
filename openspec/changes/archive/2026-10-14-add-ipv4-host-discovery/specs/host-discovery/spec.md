# Spec Delta

## Purpose

Обнаруживать отвечающие IPv4-адреса собственными сетевыми пробами, выбирая способы по маршруту и не объявляя молчащие хосты отсутствующими.

## ADDED Requirements

### Requirement: Методы обнаружения
Обнаружение должно (SHALL) поддерживать `auto`, `arp`, `icmp`, `tcp` и `raw_tcp`. `tcp` использует connect к 80/443 либо явно выбранным портам; `icmp` использует echo и timestamp; `raw_tcp` использует SYN 443 и ACK 80. На Linux raw-методы должны (SHALL) работать без Nmap и собственного нативного helper.

#### Scenario: Полный набор удалённых проб
- **WHEN** выбран `auto` с доступными raw-методами для маршрутизируемого адреса
- **THEN** используются ICMP echo/timestamp, TCP SYN 443 и ACK 80
- **AND** подтверждение любым методом прекращает оставшуюся проверку адреса

#### Scenario: TCP без привилегий
- **WHEN** выбран `tcp` для loopback с открытым либо закрытым тестовым портом
- **THEN** успешное соединение или отказ подтверждает отвечающий адрес

### Requirement: Автоматический маршрутный выбор
`auto` должен (SHALL) выбирать ARP только для непосредственно подключённого Ethernet-сегмента по маршруту ядра; для остальных адресов использовать ICMP/raw TCP. Собственный адрес должен (SHALL) подтверждаться как `local`. Отсутствие raw-привилегий должно (SHALL) приводить к явно сообщаемому TCP fallback; недоступный явно выбранный метод должен возвращать ошибку до отправки проб.

#### Scenario: Локальный сегмент
- **WHEN** маршрут цели не имеет шлюза и ведёт на Ethernet-интерфейс
- **THEN** `auto` использует ARP и возвращает MAC из подходящего ответа
- **AND** отсутствие ARP-ответа не запускает тысячи TCP-проб

#### Scenario: VPN и шлюз
- **WHEN** маршрут имеет шлюз либо не поддерживает Ethernet ARP
- **THEN** `auto` не отправляет ARP для целевого адреса

#### Scenario: Нет raw-привилегий
- **WHEN** raw-сокеты недоступны из-за прав
- **THEN** `auto` сообщает предупреждение о TCP fallback
- **AND** явный raw-метод возвращает ошибку недоступности

### Requirement: Проверка доказательств
Обнаружение должно (SHALL) принимать только корректные ответы, совпадающие с адресом и идентификаторами текущей пробы. ARP проверяет sender/target IP и MAC, ICMP — тип, code, id, sequence и данные, TCP — адреса, порты, флаги и sequence/ack. Неподходящие, повреждённые и чужие пакеты должны (SHALL) игнорироваться.

#### Scenario: Подмена и повреждение
- **WHEN** поступает усечённый пакет, неверная checksum или ответ на чужую пробу
- **THEN** адрес не подтверждается этим пакетом

#### Scenario: Ошибка маршрутизатора
- **WHEN** приходит ICMP unreachable от промежуточного узла
- **THEN** такой ответ не подтверждает целевой хост

### Requirement: Ограниченное ожидание и повторы
Ожидание должно (SHALL) использовать монотонное время, конечный срок на адрес, ограниченное число повторов и RTT-адаптацию с нижней/верхней границами. Число одновременно активных сетевых проб должно (SHALL) учитывать глобальный лимит вместе с TCP scan и индивидуальный лимит discover.

#### Scenario: Потери и предел ожидания
- **WHEN** первая отправка не получила ответа
- **THEN** проба повторяется в пределах настроенного числа повторов и срока на адрес
- **AND** по истечении срока результат равен `no_response`, не утверждая отсутствия устройства

#### Scenario: Совместная нагрузка
- **WHEN** scan и discover выполняются одновременно
- **THEN** совокупные активные пробы не превышают глобальный лимит

### Requirement: Полные результаты адресов
На каждый уникальный адрес обнаружение должно (SHALL) возвращать ровно один результат `up`, `no_response` или `error`, с длительностью и способом подтверждения для `up`. Причина ошибки должна (SHALL) сохраняться отдельно от отсутствия ответа. Сам `scan` не должен автоматически исключать не обнаруженные адреса.

#### Scenario: Молчание и ошибки
- **WHEN** все разрешённые пробы истекли либо транспорт не смог выполнить проверку
- **THEN** различаются `no_response` и `error`
- **AND** ни один исход не объявляет компьютер отсутствующим
