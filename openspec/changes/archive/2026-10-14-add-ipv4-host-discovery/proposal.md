# Proposal

## Why

Пользователю нужен поиск отвечающих хостов, а не проверка тысячи портов на каждом адресе. Собственное обнаружение с ARP и набором ICMP/TCP-проб позволяет существенно сократить работу в локальной сети и повысить полноту поиска за маршрутизатором без зависимости от Nmap.

## What Changes

- Добавить отдельные API и CLI `discover` для IPv4, не меняя семантику `scan`.
- На Linux реализовать ARP, ICMP echo/timestamp, TCP SYN 443 и ACK 80 стандартным `socket` OTP 27, без собственного C, NIF, helper и запуска Nmap.
- `auto` выбирает метод по маршруту ядра для каждого адреса; без raw-привилегий явно сообщает о переходе на TCP connect 80/443.
- Ограничивать активные пробы глобально совместно со scan, повторять потерянные пробы, адаптировать ожидание к RTT, освобождать ресурсы при любом завершении.
- Выводить подтверждённые адреса потоково, прогресс по адресам и полный JSON по запросу. Отсутствие ответа не означает отсутствие хоста.
- Сохранить Apache-2.0 и отсутствие runtime-зависимостей вне OTP.

## Capabilities

### New Capabilities

- `host-discovery`: протоколы, маршрутный выбор, доказательства ответа, собственные транспорт и политика ожидания.
- `discovery-api`: синхронное/асинхронное обнаружение, статус, отмена и жизненный цикл под supervision.
- `discovery-cli`: отдельная команда, параметры, находки, прогресс, JSON и диагностика привилегий.

### Modified Capabilities

Нет. Действующее TCP-сканирование и выборки адресов сохраняют контракт.

## Impact

Новые Erlang-модули пакетов, маршрутов, транспорта и координатора, экспорты `trawler`, интеграция с существующими supervisor/registry/scheduler, CLI и тесты. Raw-методы ограничены Linux и требуют сетевых привилегий; TCP connect доступен без root. IPv6, UDP-discovery, определение ОС/сервисов, DNS/MAC vendor database, точное воспроизведение всех эвристик Nmap и обещание идентичных результатов исключены. Никакие системные capabilities или firewall-правила автоматически не изменяются.
