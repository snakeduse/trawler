# Trawler

Встраиваемое Erlang/OTP-приложение для поиска доступных TCP-портов по IPv4-адресам,
спискам адресов, диапазонам и CIDR. Отдельный CLI использует то же ядро.

Сканер выполняет TCP connect без повышенных привилегий и поддерживает IPv4:
отдельные адреса, списки, включительные диапазоны полных адресов, CIDR
и пооктетные выражения, а также номера и включительные диапазоны портов.
Доступны асинхронный
(`trawler:start_scan/3`) и синхронный (`trawler:scan/3`) Erlang API, просмотр
прогресса (`trawler:status/1`) и отмена (`trawler:cancel/1`).

## Форматы выборок адресов

Выборка адресов задаётся в одном значении `--targets` и в Erlang API
(`trawler_targets:parse_targets/1`). Поддерживаются старые и пооктетные формы.

Старые формы — одиночный IPv4, CIDR и включительный диапазон полных адресов:

- `192.0.2.1`;
- `192.0.2.9/29` — включает адреса `192.0.2.8`..`192.0.2.15`, биты хоста нормализуются;
- `192.0.2.10-192.0.2.20`.

Старый список перечисляется через запятую, пробелы вокруг элементов допустимы:

```bash
--targets ' 192.0.2.1 , 192.0.2.4/30 , 192.0.2.10-192.0.2.11 '
```

Пооктетное выражение содержит ровно четыре октета через точку; октет — непустой
список десятичных чисел `0`..`255` и включительных диапазонов через запятую:

- `192.0.2.1-3` — последний октет `1`..`3`;
- `192.168.3-5,7.1,3-4` — третий октет из `3,4,5,7`, четвёртый из `1,3,4`;
- `10-11.20-21.30-31.40-41` — диапазоны во всех четырёх октетах;
- `192.0.2.10-`, `192.0.2.-20`, `192.0.2.-` — открытые границы: пропущенная
  левая граница означает `0`, правая — `255`;
- `192.0.2.-1` — последний октет принимает значения `0` и `1`.

Правила и ограничения:

- пробелы внутри одного выражения, ведущие нули, знаки, обратные границы,
  двойной дефис и пустые элементы запрещены;
- CIDR сочетается только с обычным одиночным адресом: `10-11.0.0.1/24` отклоняется;
- новые выражения разделяются ASCII-пробелом, табуляцией или переводом строки,
  и каждый фрагмент — либо старый список, либо одно пооктетное выражение;
  смешивать пооктетные выражения через запятую нельзя;
- бинарный элемент Erlang-списка — всегда одна цель, пооктетная в том числе;
  только общий бинарный ввод допускает список целей;
- порядок и пересечения целей не важны: каждый уникальный адрес выбирается
  ровно один раз.

```bash
--targets '192.0.2.1,3-4 198.51.100.0/30,198.51.100.7'
```

Здесь первый фрагмент — пооктетная цель `192.0.2.1,3-4` (последний октет
`1,3,4`), второй — старый список `198.51.100.0/30,198.51.100.7`.

Лимит `max_hosts` (по умолчанию 65536) применяется к объединению уникальных
адресов всех целей, а не к сумме размеров с повторами. Размер пооктетного
произведения проверяется до его разворачивания: `-.-.-.-` возвращает
`too_many_hosts`, не материализуя пространство IPv4, а CIDR и полные диапазоны
остаются сжатыми.

## Окружение

| Инструмент | Версия |
| --- | --- |
| Erlang/OTP | 27.3.4.18 |
| rebar3 | 3.27.3 |
| Node.js | 24.15.0 |
| OpenSpec | 1.14.1, глобальная установка |

На текущей машине OTP установлен через Kerl в `$HOME/erlang/27.3.4.18`.
Обёртки в `scripts/` подключают его автоматически. Для другого пути задайте
`TRAWLER_OTP_ROOT`; при отсутствии Kerl-активации используется OTP 27 из `PATH`.
Версии также закреплены в `.tool-versions` и `.nvmrc`.

OpenSpec устанавливается глобально в выбранную версию Node:

```bash
source "$HOME/.nvm/nvm.sh"
nvm use 24.15.0
npm install -g @fission-ai/openspec@1.14.1
./scripts/openspec --version
```

Смена версии Node через NVM меняет доступные глобальные пакеты. Для команд OpenSpec
используйте обёртку проекта. Сборке и работе Erlang-библиотеки Node не требуется.

```bash
make build

source scripts/env.sh otp
_build/default/bin/trawler --help
```

`make docs` создаёт EDoc, `make shell` запускает оболочку с приложением.

## Использование CLI

```bash
_build/default/bin/trawler scan \
  --targets '192.0.2.1,192.0.2.10-192.0.2.20,198.51.100.0/30' \
  --ports '22,80,443,8000-8010'
```

`--targets` обязателен, `--ports` необязателен. Без `--ports` сканируются
1000 наиболее популярных TCP-портов частотного рейтинга `nmap-services`
(дистрибутив nmap), упорядоченных по убыванию частоты:

```bash
_build/default/bin/trawler scan --targets 127.0.0.1
```

Выводит таблицу «IP / порт / состояние» и итоговую сводку. С `--json` результат
печатается одним JSON-объектом с полями `results` и `summary`:

```bash
_build/default/bin/trawler scan --targets 127.0.0.1 --ports 22,80 --json
```

Необязательные параметры: `--ports <порты>` (по умолчанию — 1000 наиболее
популярных портов nmap), `--timeout <мс>` (таймаут одной пробы, по умолчанию 1000)
и `--concurrency <n>` (одновременных проб, по умолчанию 64). Код выхода: 0 —
сканирование завершено (в том числе без открытых портов), 2 — неверные аргументы,
1 — ошибка выполнения. Диагностика направляется в stderr, результаты — в stdout.

## Подключение к другому Erlang-приложению

После публикации изменений в Git добавьте зависимость в `rebar.config`, заменив
`<commit>` на реальный SHA опубликованной версии:

```erlang
{deps, [{trawler, {git, "https://github.com/snakeduse/trawler.git",
                  {ref, "<commit>"}}}]}.
```

Укажите `trawler` в `applications` файла `.app.src` приложения-потребителя.

### Erlang API

```erlang
{ok, _} = application:ensure_all_started(trawler).

%% Синхронно: результаты отсортированы по адресу и порту.
{ok, Results} = trawler:scan(<<"127.0.0.1">>, <<"22,80,443">>, #{}),
[#{ip := {127, 0, 0, 1}, port := Port, state := State} || _ <- Results].

%% Порты можно опустить: атом default выбирает 1000 наиболее популярных портов.
{ok, DefaultResults} = trawler:scan(<<"127.0.0.1">>, default, #{}),

%% Асинхронно: результаты и ровно одно завершающее событие приходят получателю.
{ok, Ref} = trawler:start_scan(<<"192.0.2.0/30">>, <<"22,80">>, #{}),
receive {trawler, Ref, {result, R}} -> ... end,        %% по мере завершения проб
receive {trawler, Ref, {done, Summary}} -> ... end.    %% ровно одно завершение

{ok, Status} = trawler:status(Ref),                    %% состояние и счётчики
ok = trawler:cancel(Ref).                              %% идемпотентная отмена
```

Каждая проба возвращает карту с полями `ip`, `port`, `state`
(`open | closed | timeout | unreachable | error`) и `elapsed_ms`; для недоступности
и ошибки добавляется `reason`. Опции: `timeout_ms`, `concurrency`, `deadline_ms`
и `recipient` (только асинхронный API). Завершённый статус хранится 60 секунд.

## Ограничения ресурсов и результатов

Число одновременных проб ограничено глобально (`max_concurrency`, по умолчанию 256)
и для каждого сканирования (`concurrency`, по умолчанию 64). Число уникальных хостов
ограничено `max_hosts` (по умолчанию 65536) и считается по объединению уникальных
адресов всех целей, а не по сумме размеров с повторами; превышение возвращает
`too_many_hosts` до любых сетевых операций. Размер пооктетного произведения
проверяется до его разворачивания, поэтому чрезмерная цель не материализуется.
Полное декартово произведение «адреса × порты» в памяти
не создаётся: задания порождаются по мере необходимости.

TCP connect не доказывает отсутствие хоста и не различает все режимы межсетевого
экрана: `timeout` означает только отсутствие ответа за отведённое время и не
объявляется фильтрацией порта. Адрес без открытых портов не объявляется
отсутствующим в сети.

## Hermes: Sol планирует, Flash реализует

```bash
./scripts/hermes --version
./scripts/hermes doctor
./scripts/hermes skills list
./scripts/hermes chat
```

Конфигурация проекта — `.hermes/config.yaml`; локальное состояние находится в
игнорируемой `.hermes/runtime/`. Запуск не меняет основной профиль Hermes.
Деревья установленных инструментов и зависимостей Hermes используются совместно
через ссылки `runtime/tools` и `runtime/installs`; сессии и настройки изолированы.
Ключ берётся из `DEEPSEEK_API_KEY` в окружении, затем из `.hermes/runtime/.env`,
затем из существующего `$HOME/.hermes/.env`. Используется только ключ DeepSeek;
его значение не выводится и не копируется в репозиторий.

Основной агент использует `gpt-6.1-sol` с reasoning `medium` через провайдер
`openai-codex` и транспорт `codex_responses`. Работа продолжается в Hermes;
заменять приложение на Codex для этой схемы не требуется. Используется сохранённый
вход ChatGPT в Hermes. При отсутствии входа в изолированном профиле Hermes может
штатно импортировать действующий вход Codex CLI в игнорируемое локальное состояние;
секреты не попадают в отслеживаемые файлы. Если входа нет, выполните:

```bash
./scripts/hermes auth add openai-codex
```

Sol подготавливает и валидирует OpenSpec,
автоматически поручает реализацию `deepseek-flash`, проверяет результат и тесты,
затем завершает изменение. Отдельная команда для Flash не нужна. Запрос только
на планирование или подготовку проекта оставляет задачи реализации невыполненными.
Для автоматического цикла Sol создаёт артефакты через OpenSpec CLI и продолжает
реализацию в рамках исходной задачи. Отдельный вызов `/openspec-propose` служит
только подготовке спецификаций; это правило не добавляет паузу в автоматический цикл.

Координатор расходует доступ и лимиты ChatGPT, исполнитель — отдельный баланс API
DeepSeek. Подключение через OpenAI API с оплатой по токенам в этой конфигурации
не используется. Автоматическое самообучение `auxiliary.background_review` включено
и наследует модель координатора Sol: оно обновляет память и навыки, расходуя лимиты
ChatGPT. Обычная проверка кода и тестов координатором сохраняется. Пустые `fallback_providers`
запрещают скрытый переход на другую платную модель при ошибке или исчерпании лимита.
Настройки применяются при новом запуске Hermes. Наличие сохранённого входа и
корректного YAML не доказывает доступ к Sol: его подтверждает успешный запрос.

В сессии доступны навыки `/openspec-propose`, `/openspec-apply-change`,
`/openspec-update-change`, `/openspec-sync-specs`, `/openspec-explore`,
`/openspec-archive-change`. Инструкции и критерии работы находятся в `AGENTS.md`.

```bash
./scripts/openspec list
./scripts/openspec status --change add-tcp-ipv4-scanner
make specs
```

Первая версия ограничена TCP и IPv4. IPv6, UDP, ICMP/ARP, определение ОС и
веб-интерфейс оставлены последующим версиям. TCP-таймаут не означает отсутствия хоста.

## Язык инструкций и спецификаций

`AGENTS.md`, документы OpenSpec и пояснения к настройкам написаны по-русски.
Это правило действует и для новых документов проекта. Стандартные навыки
`.hermes/skills/*/SKILL.md` сохраняют исходный английский текст.
Команды, API, ключи YAML/JSON и служебные маркеры
OpenSpec сохраняют исходное написание. `SHALL` и `MUST` означают обязательное
требование; `WHEN`, `THEN`, `AND` — «когда», «тогда», «и».
