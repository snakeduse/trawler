# Trawler

Встраиваемое Erlang/OTP-приложение для поиска доступных TCP-портов по IPv4-адресам,
спискам адресов, диапазонам и CIDR. Отдельный CLI использует то же ядро.

Сканер выполняет TCP connect без повышенных привилегий и поддерживает IPv4:
отдельные адреса, списки, включительные диапазоны полных адресов, CIDR
и пооктетные выражения, а также номера и включительные диапазоны портов.
Доступны асинхронный
(`trawler:start_scan/3`) и синхронный (`trawler:scan/3`) Erlang API, просмотр
прогресса (`trawler:status/1`) и отмена (`trawler:cancel/1`).

## Форматы выборок адресов

Выборка адресов задаётся в одном значении `--targets` и в Erlang API
(`trawler_targets:parse_targets/1`). Поддерживаются старые и пооктетные формы.

Старые формы — одиночный IPv4, CIDR и включительный диапазон полных адресов:

- `192.0.2.1`;
- `192.0.2.9/29` — включает адреса `192.0.2.8`..`192.0.2.15`, биты хоста нормализуются;
- `192.0.2.10-192.0.2.20`.

Старый список перечисляется через запятую, пробелы вокруг элементов допустимы:

```bash
--targets ' 192.0.2.1 , 192.0.2.4/30 , 192.0.2.10-192.0.2.11 '
```

Пооктетное выражение содержит ровно четыре октета через точку; октет — непустой
список десятичных чисел `0`..`255` и включительных диапазонов через запятую:

- `192.0.2.1-3` — последний октет `1`..`3`;
- `192.168.3-5,7.1,3-4` — третий октет из `3,4,5,7`, четвёртый из `1,3,4`;
- `10-11.20-21.30-31.40-41` — диапазоны во всех четырёх октетах;
- `192.0.2.10-`, `192.0.2.-20`, `192.0.2.-` — открытые границы: пропущенная
  левая граница означает `0`, правая — `255`;
- `192.0.2.-1` — последний октет принимает значения `0` и `1`.

Правила и ограничения:

- пробелы внутри одного выражения, ведущие нули, знаки, обратные границы,
  двойной дефис и пустые элементы запрещены;
- CIDR сочетается только с обычным одиночным адресом: `10-11.0.0.1/24` отклоняется;
- новые выражения разделяются ASCII-пробелом, табуляцией или переводом строки,
  и каждый фрагмент — либо старый список, либо одно пооктетное выражение;
  смешивать пооктетные выражения через запятую нельзя;
- бинарный элемент Erlang-списка — всегда одна цель, пооктетная в том числе;
  только общий бинарный ввод допускает список целей;
- порядок и пересечения целей не важны: каждый уникальный адрес выбирается
  ровно один раз.

```bash
--targets '192.0.2.1,3-4 198.51.100.0/30,198.51.100.7'
```

Здесь первый фрагмент — пооктетная цель `192.0.2.1,3-4` (последний октет
`1,3,4`), второй — старый список `198.51.100.0/30,198.51.100.7`.

Лимит `max_hosts` (по умолчанию 65536) применяется к объединению уникальных
адресов всех целей, а не к сумме размеров с повторами. Размер пооктетного
произведения проверяется до его разворачивания: `-.-.-.-` возвращает
`too_many_hosts`, не материализуя пространство IPv4, а CIDR и полные диапазоны
остаются сжатыми.

```bash
source "$HOME/.nvm/nvm.sh"
nvm use 24.15.0
npm install -g @fission-ai/openspec@1.14.1
./scripts/openspec --version
```

Смена версии Node через NVM меняет доступные глобальные пакеты. Для команд OpenSpec
используйте обёртку проекта. Сборке и работе Erlang-библиотеки Node не требуется.

## Использование CLI

```bash
_build/default/bin/trawler scan \
  --targets '192.0.2.1,192.0.2.10-192.0.2.20,198.51.100.0/30' \
  --ports '22,80,443,8000-8010'
```

`--targets` обязателен, `--ports` необязателен. Без `--ports` сканируются
1000 наиболее популярных TCP-портов частотного рейтинга `nmap-services`
(дистрибутив nmap), упорядоченных по убыванию частоты:

```bash
_build/default/bin/trawler scan --targets 127.0.0.1
```

Без `--json` текст печатает открытые порты сразу по мере обнаружения, а по
завершении — компактную сводку со счётчиками всех исходов (пример вывода):

```
IP               PORT    STATE
192.0.2.10       22      open
Завершено: 3 из 3 проб за 412 мс
Открытых портов: 1
Закрыто: 2
Без ответа (таймаут): 0
Недоступно: 0
Ошибки: 0
```

По умолчанию перечисляются только открытые порты; закрытые порты, таймауты,
недоступность и ошибки видны счётчиками, а не списком адресов. `--verbose`
добавляет каждую пробу с IP, портом и состоянием (`open`, `closed`, `timeout`,
`unreachable`, `error`). Когда открытых портов нет, сводка явно сообщает об этом
и не объявляет адрес отсутствующим в сети.

Прогресс идёт в stderr: в терминале это одна обновляемая строка, например
`Проверено 512/1000 (51%) | открыто 3 | 2 с` (значения показаны для
иллюстрации), при перенаправлении — редкие строки без ANSI и возврата каретки.
Начало и завершение печатаются всегда. `--no-progress` отключает прогресс;
`--json` также не печатает прогресс. В терминале строка находки выводится на
очищенной строке, после чего прогресс перерисовывается.

С `--json` результат печатается одним JSON-объектом с полями `results` и
`summary`; JSON сохраняет полный прежний формат с сортированными наблюдениями и
не содержит прогресса даже с `--verbose`:

```bash
_build/default/bin/trawler scan --targets 127.0.0.1 --ports 22,80 --json
```

Необязательные параметры: `--ports <порты>` (по умолчанию — 1000 наиболее
популярных портов nmap), `--timeout <мс>` (таймаут одной пробы, по умолчанию
1000), `--concurrency <n>` (одновременных проб, по умолчанию 64) и флаги
`--verbose`, `--no-progress`. Повтор любого ключа или флага отклоняется с кодом 2.
Код выхода: 0 — сканирование завершено (в том числе без открытых портов),
2 — неверные аргументы, 1 — ошибка выполнения. Диагностика направляется в stderr,
результаты — в stdout. Таймаут относится к одной пробе и не означает отсутствия
компьютера.

## Обнаружение хостов (discover)

`discover` ищет отвечающие IPv4-адреса, а не открытые порты всех хостов.
Выборка `--targets` понимает те же форматы, что `scan`: одиночный адрес,
старый список, CIDR, полный диапазон и пооктетные выражения.

```bash
source scripts/env.sh otp
_build/default/bin/trawler discover \
  --targets '127.0.0.1,192.0.2.0/30' --method auto
```

С `--method auto` метод выбирается по маршруту ядра для каждого адреса: ARP —
только для непосредственно подключённого Ethernet-сегмента, ICMP echo/timestamp
и raw TCP SYN 443/ACK 80 — для остальных; собственный адрес подтверждается
локально. Без raw-привилегий auto явно сообщает о переходе на TCP connect: без
`--ports` проверяются 80/443, а с явным `--ports` — выбранный набор. Явно
выбранный raw-метод (`arp`, `icmp`, `raw_tcp`) без прав завершается ошибкой до
проб.

Текстовый режим печатает подтверждённые адреса сразу: `IP`, метод (`local`,
`arp`, `icmp_echo`, `icmp_timestamp`, `tcp_syn`, `tcp_ack`, `tcp_open`,
`tcp_refused`) и MAC при ARP. `--verbose` добавляет состояние каждого адреса
(`up`, `no_response`, `error`). Итоговая сводка сообщает число уникальных
адресов, находок, отсутствие ответа и ошибки и никогда не объявляет машину
отсутствующей:

```text
IP               МЕТОД        MAC
127.0.0.1        tcp_open     -
Завершено: 1 из 1 адресов за 4 мс
Найдено отвечающих адресов: 1
Без ответа: 0
Ошибки: 0
```

При запрошенных опциях столбцы добавляются после прежних `IP`/`МЕТОД`/`MAC`
(значения показаны для иллюстрации):

```text
IP               МЕТОД        MAC                ОС                               ОТКРЫТЫЕ ПОРТЫ
127.0.0.1        local        -                  linux (low, предположение)      22
```

Параметры:

- `--method auto|arp|icmp|tcp|raw_tcp`, по умолчанию auto;
- `--ports <порты>` — необязательные дополнительные проверки найденных
  адресов при любом методе. Порты и диапазоны перечисляются через запятую;
  по умолчанию tcp/auto проверяют 80/443. Ограничения в 16 портов нет, но
  набор из 65535 значений может не успеть за бюджет адреса: непроверенные
  явные порты возвращаются как `skipped`, а не выдаются за закрытые.
  Открытость портов **не фильтрует** найденные IP: адрес с закрытыми или
  молчащими портами остаётся находкой;
- `--os` — неповторяемый флаг приблизительной классификации ОС (`windows`,
  `linux`, `unknown`) с уверенностью `medium|low|none` и основаниями. По
  умолчанию выключен; открытый SSH или SMB — слабый признак, а не
  доказательство семьи ОС. `unknown` допустим и печатается как есть;
- `--timeout <мс>` — конечный бюджет всего адреса (по умолчанию 1000): поиск
  маршрута, проба обнаружения, чтение баннера и проверка портов вместе;
- `--concurrency <n>` (по умолчанию 64), `--retries <0..5>` (по умолчанию 2);
- флаги `--json`, `--verbose`, `--no-progress`.

Повтор любого ключа или флага, неизвестный ключ и пропущенное значение
отклоняются с кодом 2 до сетевых проб. Коды выхода: 0 — поиск завершён
(включая отсутствие находок и ошибки отдельных адресов), 1 — недоступный
метод, ошибка запуска или выполнения, 2 — неверные аргументы. Прогресс и
предупреждения идут в stderr, находки и JSON — в stdout.

С `--json` печатается один полный объект с отсортированными `results` и
`summary`, где `warnings` — список строк; прогресса нет, а предупреждение о TCP
fallback по-прежнему уходит в stderr. Дополнительные данные сохраняются
полностью: у найденного адреса при `--ports` есть `port_results` (все явные
порты с состояниями `open|closed|timeout|unreachable|error|skipped`,
длительностью и необязательной причиной) и `open_ports` (только открытые явно
выбранные порты), при `--os` — `os` с `family`, `confidence` и `evidence`.
Неожиданная ошибка инспектора не скрывает адрес: он остаётся `up`, а причина
передаётся строкой `inspection_error`. Пример, который можно выполнить на
loopback:

```bash
_build/default/bin/trawler discover --targets 127.0.0.1 \
  --ports 22,445 --os --json
```

### Привилегии и ограничения raw

- Raw-методы (`arp`, `icmp`, `raw_tcp`) работают только на Linux и требуют
  сетевых привилегий (`CAP_NET_RAW` или root). TCP connect доступен без root.
- Trawler не меняет системные capabilities и firewall автоматически: никакого
  `setcap` при установке не выполняется. Привилегии выдаются явно на запуск.
- Одновременно на адрес держится одна активная проба; поздний ответ на закрытую
  пробу теряется (осознанный размен первой версии), а потерянные пробы
  повторяются в пределах `--timeout`.
- `--timeout` — жёсткий бюджет адреса, а не отдельного пакета: он покрывает и
  поиск маршрута, и все виды проб адреса, и дополнительные проверки портов.
- Raw TCP использует фиксированные порты SYN 443 и ACK 80 для самого
  обнаружения; `--ports` не меняет эти пробы, но разрешён как дополнительные
  проверки уже найденных адресов.
- Proxy ARP отвечает за адрес, а не за отдельное устройство: одинаковый MAC у
  разных адресов — не ошибка.
- `discover` не является обёрткой над Nmap, не устанавливает ПО, не выдаёт и не
  подтверждает права, не меняет firewall и не обещает точного совпадения с
  результатами Nmap или полноты его эвристик; молчащий хост не объявляется
  отсутствующим.

Реальную проверку raw-проб на loopback (ICMP echo/timestamp, raw SYN/ACK) можно
выполнить явной opt-in командой. В `make check` она не входит: нужны сетевые
права, а библиотечное ядро root не требует. Абсолютный путь к escript нужен,
чтобы после `sudo` нашлись OTP 27 и сборка:

```bash
source scripts/env.sh otp
sudo -n env "HOME=$HOME" "PATH=$PATH" "TRAWLER_ROOT=$PWD" \
  escript "$PWD/scripts/check-discovery-raw.escript"
# или обёрткой: она подключит OTP и при необходимости перезапустит через sudo -n.
scripts/check-discovery-raw
```

### Erlang API обнаружения

```erlang
{ok, _} = application:ensure_all_started(trawler),
{ok, Results, Summary} =
    trawler:discover(<<"127.0.0.1">>,
                     #{method => auto, ports => [22, 445],
                       os_detection => true}),
%% `:=` допустим только в образце, поэтому отбор по адресу идёт
%% генератором, а шаблон понимания списка лишь выбирает поля.
[{maps:get(port_results, R, []), maps:get(os, R, undefined)}
 || #{ip := {127, 0, 0, 1}, state := State} = R <- Results,
    State =:= up],
maps:get(counters, Summary).

{ok, Ref} = trawler:start_discovery(<<"192.0.2.0/30">>,
                                    #{method => auto, recipient => self()}),
receive {trawler_discovery, Ref, {result, AsyncResult}} -> ok end, %% находки
receive {trawler_discovery, Ref, {done, AsyncSummary}} -> ok end,
{ok, Status} = trawler:discovery_status(Ref),
%% Пока задание активно, отмена возвращает ok; для уже завершённого —
%% {error, already_finished}.
Cancel = trawler:cancel_discovery(Ref).
```

Каждый уникальный адрес даёт ровно один результат `up | no_response | error` с
`elapsed_ms`; у `up` есть `method`, у ARP — `mac`, у TCP — `port`. `no_response`
не означает отсутствия компьютера. `ports` допустим при любом методе: это
дополнительные проверки найденных адресов (`port_results`, `open_ports`), а не
фильтр IP. `os_detection => true` добавляет `os` с `family`, `confidence` и
`evidence`; по умолчанию равно `false`. Не успевшие за `timeout_ms` явные порты
получают `skipped`, а ОС может остаться `unknown`; `timeout_ms` — общий бюджет
маршрута, пробы, чтения баннера и проверок портов. Атом `default` в `ports`
выбирает 1000 популярных портов: набор принимается, но может не успеть целиком.
Неожиданное исключение инспектора не отменяет `up` и возвращает
`inspection_error`. Опции: `method`, `ports`, `os_detection`, `timeout_ms`,
`concurrency`, `retries`, `deadline_ms`, `recipient`.

## Подключение к другому Erlang-приложению

После публикации изменений в Git добавьте зависимость в `rebar.config`, заменив
`<commit>` на реальный SHA опубликованной версии:

```erlang
{deps, [{trawler, {git, "https://github.com/snakeduse/trawler.git",
                  {ref, "<commit>"}}}]}.
```

Укажите `trawler` в `applications` файла `.app.src` приложения-потребителя.

### Erlang API

```erlang
{ok, _} = application:ensure_all_started(trawler).

%% Синхронно: результаты отсортированы по адресу и порту.
{ok, Results} = trawler:scan(<<"127.0.0.1">>, <<"22,80,443">>, #{}),
[{Port, State} || #{ip := {127, 0, 0, 1}, port := Port, state := State} <- Results].

%% Порты можно опустить: атом default выбирает 1000 наиболее популярных портов.
{ok, DefaultResults} = trawler:scan(<<"127.0.0.1">>, default, #{}),

%% Асинхронно: результаты и ровно одно завершающее событие приходят получателю.
{ok, Ref} = trawler:start_scan(<<"192.0.2.0/30">>, <<"22,80">>, #{}),
receive {trawler, Ref, {result, R}} -> ... end,        %% по мере завершения проб
receive {trawler, Ref, {done, Summary}} -> ... end.    %% ровно одно завершение

{ok, Status} = trawler:status(Ref),                    %% состояние и счётчики
ok = trawler:cancel(Ref).                              %% идемпотентная отмена
```

Каждая проба возвращает карту с полями `ip`, `port`, `state`
(`open | closed | timeout | unreachable | error`) и `elapsed_ms`; для недоступности
и ошибки добавляется `reason`. Опции: `timeout_ms`, `concurrency`, `deadline_ms`
и `recipient` (только асинхронный API). Завершённый статус хранится 60 секунд.

## Ограничения ресурсов и результатов

Число одновременных проб ограничено глобально (`max_concurrency`, по умолчанию 256)
и для каждого сканирования (`concurrency`, по умолчанию 64). Число уникальных хостов
ограничено `max_hosts` (по умолчанию 65536) и считается по объединению уникальных
адресов всех целей, а не по сумме размеров с повторами; превышение возвращает
`too_many_hosts` до любых сетевых операций. Размер пооктетного произведения
проверяется до его разворачивания, поэтому чрезмерная цель не материализуется.
Полное декартово произведение «адреса × порты» в памяти
не создаётся: задания порождаются по мере необходимости.

TCP connect не доказывает отсутствие хоста и не различает все режимы межсетевого
экрана: `timeout` означает только отсутствие ответа за отведённое время и не
объявляется фильтрацией порта. Адрес без открытых портов не объявляется
отсутствующим в сети.

```bash
./scripts/hermes skills list
./scripts/hermes chat
```

Конфигурация проекта — `.hermes/config.yaml`; локальное состояние находится в
игнорируемой `.hermes/runtime/`. Запуск не меняет основной профиль Hermes.
Деревья установленных инструментов и зависимостей Hermes используются совместно
через ссылки `runtime/tools` и `runtime/installs`; сессии и настройки изолированы.
Ключ берётся из `DEEPSEEK_API_KEY` в окружении, затем из `.hermes/runtime/.env`,
затем из существующего `$HOME/.hermes/.env`. Используется только ключ DeepSeek;
его значение не выводится и не копируется в репозиторий.

Основной агент использует `gpt-6.1-sol` с reasoning `medium` через провайдер
`openai-codex` и транспорт `codex_responses`. Работа продолжается в Hermes;
заменять приложение на Codex для этой схемы не требуется. Используется сохранённый
вход ChatGPT в Hermes. При отсутствии входа в изолированном профиле Hermes может
штатно импортировать действующий вход Codex CLI в игнорируемое локальное состояние;
секреты не попадают в отслеживаемые файлы. Если входа нет, выполните:

```bash
./scripts/hermes auth add openai-codex
```

Sol подготавливает и валидирует OpenSpec,
автоматически поручает реализацию `deepseek-flash`, проверяет результат и тесты,
затем завершает изменение. Отдельная команда для Flash не нужна. Запрос только
на планирование или подготовку проекта оставляет задачи реализации невыполненными.
Для автоматического цикла Sol создаёт артефакты через OpenSpec CLI и продолжает
реализацию в рамках исходной задачи. Отдельный вызов `/openspec-propose` служит
только подготовке спецификаций; это правило не добавляет паузу в автоматический цикл.

Координатор расходует доступ и лимиты ChatGPT, исполнитель — отдельный баланс API
DeepSeek. Подключение через OpenAI API с оплатой по токенам в этой конфигурации
не используется. Автоматическое самообучение `auxiliary.background_review` включено
и наследует модель координатора Sol: оно обновляет память и навыки, расходуя лимиты
ChatGPT. Обычная проверка кода и тестов координатором сохраняется. Пустые `fallback_providers`
запрещают скрытый переход на другую платную модель при ошибке или исчерпании лимита.
Настройки применяются при новом запуске Hermes. Наличие сохранённого входа и
корректного YAML не доказывает доступ к Sol: его подтверждает успешный запрос.

В сессии доступны навыки `/openspec-propose`, `/openspec-apply-change`,
`/openspec-update-change`, `/openspec-sync-specs`, `/openspec-explore`,
`/openspec-archive-change`. Инструкции и критерии работы находятся в `AGENTS.md`.

```bash
./scripts/openspec list
./scripts/openspec status --change add-tcp-ipv4-scanner
make specs
```

Обнаружение работает по IPv4 и поддерживает TCP connect, ARP и ICMP/raw TCP;
предположение об ОС приблизительное. IPv6, UDP, полноценный fingerprinting в
стиле Nmap и веб-интерфейс оставлены последующим версиям. TCP-таймаут не
означает отсутствия хоста.

## Язык инструкций и спецификаций

`AGENTS.md`, документы OpenSpec и пояснения к настройкам написаны по-русски.
Это правило действует и для новых документов проекта. Стандартные навыки
`.hermes/skills/*/SKILL.md` сохраняют исходный английский текст.
Команды, API, ключи YAML/JSON и служебные маркеры
OpenSpec сохраняют исходное написание. `SHALL` и `MUST` означают обязательное
требование; `WHEN`, `THEN`, `AND` — «когда», «тогда», «и».
